# Infralink v0.4.0

Infralink `v0.4.0` publishes the manifest-bound publisher request v3 contract.
The contract binds a release request to its canonical immutable manifest before
admission, preventing a request from being reinterpreted against different
candidate evidence.

## Compatibility

- Python 3.10, 3.11, and 3.12 on supported POSIX/Linux systems.
- Every CLI invocation continues to emit one `infralink.cli/v1` JSON envelope.
- Publisher request and attestation v2 contracts remain available for existing
  consumers; v3 is the strict manifest-bound contract for new release work.
- Existing `v0.2.0` and `v0.3.0` artifacts, tags, and release records remain
  immutable historical records.

## Release Evidence

Woodpecker remains the sole build and release executor. A manual release runs
for `main` on Python 3.12 after the parallel Python 3.10-3.12 quality gates. It
requires `RELEASE_VERSION` and the package version to match, verifies that the
pipeline commit is the current `main` commit, and stops if the corresponding
tag or GitHub release already exists.

The GitHub release contains exactly:

```text
infralink-0.4.0-py3-none-any.whl
infralink-0.4.0.tar.gz
SHA256SUMS
SHA256SUMS.sigstore.json
```

The checksum file covers the wheel and sdist in canonical order. The Cosign
bundle signs that checksum file with the Woodpecker release key. This release
uses the existing Woodpecker-only manual step; it does not add GitHub Actions,
GHCR, a fleet deployment, registry mutation, or PyPI upload.

## Adoption And Rollback

Consumers record the release tag, source commit, and wheel digest before
adoption. Rollback restores the previously verified consumer revision and
digest; it does not rebuild old source or mutate existing release records.
