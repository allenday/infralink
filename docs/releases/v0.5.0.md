# Infralink v0.5.0

Infralink `v0.5.0` adds the typed `host_metrics` operations view. The registry
declares its metrics-capable service profile and datasource once; the planner
derives membership from all matching declared service instances.

## Compatibility

- Python 3.10, 3.11, and 3.12 on supported POSIX/Linux systems.
- Every CLI invocation emits one structured `infralink.cli/v1` envelope: YAML
  by default, or JSON when `--output json` is specified.
- Existing operations-view kinds remain unchanged. `host_metrics` is an
  additive, public observation schema kind.
- Existing release tags and artifacts remain immutable historical records.

## Release Evidence

Woodpecker remains the sole build and release executor. A manual release runs
for `main` on Python 3.12 after the parallel Python 3.10-3.12 quality gates. It
requires `RELEASE_VERSION=0.5.0`, confirms that the pipeline commit is current
`main`, and stops if the tag or GitHub release already exists.

The GitHub release contains exactly:

```text
infralink-0.5.0-py3-none-any.whl
infralink-0.5.0.tar.gz
SHA256SUMS
SHA256SUMS.sigstore.json
```

The checksum file covers the wheel and sdist in canonical order. The Cosign
bundle signs that checksum file with the Woodpecker release key. This release
does not introduce GitHub Actions, a fleet deployment, registry mutation, or
PyPI upload.

## Adoption And Rollback

Registry consumers pin the published immutable revision before declaring
`host_metrics`. Rollback restores the previously verified consumer revision
and digest; it does not rebuild old source or mutate existing release records.
