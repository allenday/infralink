# Infralink v0.5.4

Infralink `v0.5.4` makes the fail-closed controller bootstrap workflow
actionable for a newly provisioned host without weakening its declared
identity, Tailnet, or BWS boundaries.

## Bootstrap Diagnostics And Handoff

- `infralink host bootstrap` reports the exact manifest and deployment paths,
  required fields, and a safe `host show` action when canonical controller
  bootstrap state is absent.
- A blank host whose remaining failed readiness checks are executor-backed
  prerequisites now receives one HATEOAS `apply` handoff. It supplies the BWS
  token only through `--bws-token-stdin` and never serializes the token in the
  command response.
- Missing Docker, jq, BWS CLI, machine UUID, and controller runtime are
  bootstrap work, not operator-side prerequisites. A mismatched or missing
  declared SSH/Tailnet identity still omits the mutation handoff.

## Compatibility

- Python 3.10, 3.11, and 3.12 on supported POSIX/Linux systems.
- Existing release tags and artifacts remain immutable historical records.

## Release Evidence

Woodpecker is the sole release executor. A manual release whose commit equals
`main` requires `RELEASE_VERSION=0.5.4`, verifies the fetched `main` SHA,
and publishes the wheel, sdist, checksums, and Cosign bundle to GitHub.
