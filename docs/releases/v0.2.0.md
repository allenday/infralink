# Infralink v0.2.0

Infralink `v0.2.0` stabilizes the read-only topology API, a machine-oriented
CLI, safe connection resolution, deterministic artifacts, and optional hosted
Bitwarden Secrets Manager auditing.

## Compatibility

- Python 3.10, 3.11, and 3.12 on supported POSIX/Linux systems.
- Every CLI invocation emits one `infralink.cli/v1` JSON envelope.
- Exit codes follow the stable contract below.
- Credential-bearing CLI output and arbitrary secret lookup are removed.
  Resolution returns opaque declared references and safe connection templates;
  resolved secret values never cross the CLI serialization boundary.

| Code | Meaning |
| --- | --- |
| `0` | Positive domain result |
| `1` | Completed negative domain result |
| `2` | Usage error |
| `3` | Input, schema, or entity error |
| `4` | Provider or authentication failure |
| `69` | Unsupported platform |
| `70` | Unexpected internal failure |
| `74` | Artifact I/O failure or retained recovery state |

Exit `74` uses `artifact_io_failed` for storage failures and
`artifact_recovery_required` when recovery state is retained. `internal_error`
is reserved for exit `70`.

## Optional Hosted BWS

Install provider support with `python -m pip install "infralink[bws]"`.
Configure `BWS_ACCESS_TOKEN` and `BWS_ORGANIZATION_ID` out of band. The audit
surface is read-only and only checks secret references declared by topology.

Production `v0.2.0` accepts Bitwarden's hosted HTTPS endpoints only. Endpoint
override environment variables are rejected because the current SDK transport
cannot enforce the required redirect-origin guarantees. Custom endpoint and
custom transport support are deferred.

## Release Evidence

Woodpecker is the sole build and release executor. A manual release runs for
`main` on Python 3.12 after the parallel Python 3.10-3.12 quality gates. It
requires the requested and package versions to equal `0.2.0`, verifies that
the pipeline commit is the current `main` commit, and stops if tag or release
`v0.2.0` already exists.

The GitHub release contains exactly:

```text
infralink-0.2.0-py3-none-any.whl
infralink-0.2.0.tar.gz
SHA256SUMS
SHA256SUMS.sigstore.json
```

The checksum file covers the wheel and sdist in canonical order. The Cosign
bundle signs that checksum file with the Woodpecker release key. Private
compatibility checks may run as diagnostics, but are not a publication gate.
Configure repository secrets `infralink_release_github_token` and
`infralink_gate_cosign_private_key` for manual events only. The GitHub token
requires temporary contents-write access; the Cosign key is passwordless and
is exposed only to the release step.

## Adoption And Rollback

Adopt `v0.2.0` in `infra-management` as a separate reviewed submodule commit.
Before updating, record the existing gitlink. The immediate rollback revision
for the current consumer is:

```text
36a07e7b9cbd1927b322dd19e472146e2bd4d056
```

Rollback changes only the `third-party/infralink` gitlink to that revision and
reruns the consumer's non-deploying validation. It does not require deleting
the `v0.2.0` tag or release.

Creating `v0.2.0` performs no fleet deployment, registry mutation, service
restart, consumer submodule update, or PyPI upload.
