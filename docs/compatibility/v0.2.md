# Infralink v0.2 Compatibility

This guide describes public migration classes without reproducing private
topology.

## Consumer Inventory

A read-only search of the `infra-management` and
`infra-management-registry-main` repositories found Infralink references in 57
and 2 files respectively. A Python-only, line-anchored inventory in the
management repository found 63 anchored `from infralink` imports and
0 anchored `import infralink` module imports. The five matches from the earlier unanchored
`import infralink` substring search were four loader-module imports and one
prose comment, not direct package imports. Excluding method definitions,
syntax-aware searches found 1 PostgreSQL, 1 Redis, and 5 generic URL-helper call
sites. The registry repository contains command/config references but no Python
imports or helper call sites in this inventory.

These are snapshot counts from 2026-07-25. They guide migration sizing; they do
not assert runtime use.

## Migration Classes

### CLI automation

Parse the `infralink.cli/v1` envelope instead of line-oriented text. Check
`ok`, then the typed `result` or `error`; follow bounded `next_actions` and
continuation cursors. Treat exit `1` as a completed negative domain result, not
an execution failure.

### Python imports

Existing top-level core imports remain supported. New secret integrations
should import the provider-neutral reference and resolver types from
`infralink`; provider-specific code belongs behind the optional adapter.

### URL helpers

Legacy Python URL helpers remain available but are deprecated. Replace calls
that provide passwords with `get_connection_template()` and inject the
referenced value only at the final consumer boundary. CLI password flags and
password-bearing URL output are removed.

### Secret audit

Install `infralink[bws]` only where hosted BWS audit is required. Configure
`BWS_ACCESS_TOKEN` and `BWS_ORGANIZATION_ID` out of band. Audit accepts only
references declared by the loaded topology, performs no arbitrary lookup, and
does not return values.

### Generated artifacts

Diagram, documentation, and analysis commands require explicit output
directories on POSIX/Linux. Consume their bounded JSON artifact records rather
than generated content on stdout.

## Candidate Adoption

Download the retained GitHub Actions artifact by its numeric artifact ID.
Verify GitHub provenance, the full source commit in `manifest.json`, and
`sha256sum -c SHA256SUMS` before installing the wheel. Record the artifact ID
and wheel digest in consumer configuration.

Rollback restores the previous verified artifact ID, source commit, and digest.
Do not rebuild an old source revision and assume equivalent bytes.
